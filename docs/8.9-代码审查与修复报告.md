# AgentCut 8.8/8.9 代码审查与修复报告

## 审查范围
- 对照 `docs/AgentCut-Agent能力扩展PRD与安全设计.md`，复查 8.8/8.9 改动的后端 API、前端组件、数据模型、安全与部署相关代码。
- 重点验证：运行时稳定性、COS/本地存储统一访问、OCR/素材解析、Skill 审核流、审计日志。

## 已修复的 P0 Bug（本次已修）

### 1. `backend/app/api/skills/router.py` — admin 更新 Skill 触发 `NameError`
- **问题**：`current_status = (skill.created_at and q) or "draft"` 引用了未定义变量 `q`。任何管理员调用 `PUT /api/v1/admin/skills/{id}` 都会 500。
- **修复**：删除该行，后续状态判断使用已读取的 `original_status`。
- **验证**：TestClient 调用 `PUT /api/v1/admin/skills/{id}` 返回 200，Skill 成功变为 published。

### 2. `backend/app/services/doc_processing_service.py` — OCR 凭据缺失时返回空文本但状态为 `ready`
- **问题**：`_extract_ocr_tencent` 中 `return None, {...}` 后紧跟不可达 `raise`，导致凭据缺失时返回 `text=""`、`text_status="ready"`，用户误以为解析成功。
- **修复**：改为直接 `raise RuntimeError(...)`，由 `parse_asset` 统一捕获并返回 `text_status=failed`。
- **验证**：无 OCR 凭据时解析图片返回 `text_status: failed`，错误信息明确。

### 3. 资产/产物 COS URL 解析链断裂导致破图
- **问题**：
  - 上传/生成产物优先存 COS，返回的 `storage_key` 形如 `uploads/{user_id}/{filename}` 或 `generated/{user_id}/{filename}`。
  - 前端 `getAssetUrl()` 把任何 key 都拼成 `/api/v1/upload/{key}`，后端 `/api/v1/upload/{user_id}/{filename}` 只支持两段路径，无法解析带 prefix 的 key，导致 404/破图。
- **修复**：
  - `backend/app/services/upload_service.py`：`_file_path_for` 与 `_owner_id_for` 支持多级 key；新增 `resolve_upload_url()`，本地文件存在则返回路径，不存在且 COS 配置则返回 presigned URL。
  - `backend/app/api/upload/router.py`：路由改为 `/{storage_key:path}`，返回 `FileResponse` 或 `RedirectResponse`。
- **验证**：TestClient 上传图片后，`GET /api/v1/upload/uploads/{uid}/{filename}` 返回 307 重定向到 COS presigned URL。

## 已修复的 P1 问题（本次已修）

### 4. `backend/app/api/admin/audit_logs.py` — 时区敏感比较
- **问题**：`datetime.utcnow()` 与 `created_at`（`DateTime(timezone=True)`）比较，可能产生隐式时区转换或警告。
- **修复**：统一使用 `datetime.now(timezone.utc)`。

### 5. `backend/app/services/upload_service.py` — `cos_service` 导入不一致
- **问题**：原代码 `from app.services.cos_service import is_configured as cos_is_configured`，但 `save_upload_file` 中调用 `cos_service.is_configured()` 导致 `NameError`。
- **修复**：改为 `from app.services import cos_service`，并在新增函数中使用 `cos_service.is_configured()`。

## 仍存在的 P1/P2 问题与缺失（未修复，建议后续处理）

### 6. 数据库 Schema 迁移缺位
- **表现**：本地/线上 `users` 表缺少 `agent_model`、`agent_model_updated_at` 列，调用涉及 `User.agent_model` 的查询会 500。本次通过手动 `ALTER TABLE` 临时修复。
- **风险**：后续新增字段（`model_pricing`、`agent_audit_logs`、`user_notifications` 等）若未做迁移，生产环境随时可能因 schema 不一致崩溃。
- **建议**：引入 Alembic 或至少每次改模型时提供 `ALTER TABLE` 脚本并同步到服务器。

### 7. `backend/app/services/rate_limiter.py` — 内存级限流进程重启清零
- **问题**：当前用 `dict + deque` 存计数，多 worker/服务重启后全部清空，不符合 PRD 对“用户上传 20 次/分钟”的约束语义。
- **建议**：接入 Redis 或在 PostgreSQL 中持久化计数（如 `rate_limit_buckets` 表）。

### 8. `backend/app/api/skills/router.py` — 通知 body 可能为 None
- **问题**：`body=body.get("review_comment") or skill.review_comment` 可在两者均为 None 时传 None，虽然字段 nullable，但用户看到的通知正文为空。
- **建议**：给 `UserNotification.body` 提供默认说明，例如 `"无审核备注"`。

### 9. `backend/app/services/doc_processing_service.py` — 未显式导入 `TencentCloudSDKException`
- **问题**：通用 `except Exception` 已兜底，但无法针对腾讯云签名/额度错误做特殊降级或更友好的报错。
- **建议**：显式 `from tencentcloud.common.exception.tencent_cloud_sdk_exception import TencentCloudSDKException` 并单独捕获。

### 10. `backend/app/api/gateway/router.py` — 外部 URL 下载失败 fallback 到原始 URL
- **问题**：`_save_generated_media` 中外部 URL 下载失败时回退保存原始 URL，该 URL 可能带临时 token，会过期导致后续破图。
- **建议**：失败时记录 warning，不将不可控外部 URL 写入 `generated_files`；或增加后台重试/转存任务。

### 11. 前端 `getAssetUrl()` 仍把 COS key 当成本地路径拼接
- **问题**：虽然后端 upload router 现在能解析并 redirect，但语义上 `getAssetUrl` 仍“假设所有 key 都是本地 key”。如果后端 redirect 被浏览器/图片标签缓存策略干扰，仍可能出问题。
- **建议**：资产相关接口统一返回后端已签名的可访问 URL，前端尽量直接使用接口返回的 `url`，减少本地拼接。

### 12. `backend/app/models/skill.py` — `UserSkillBinding.skill_id` 类型不一致
- **问题**：`UserSkillBinding.skill_id = Column(String(36))`，而 `AdminSkill.id = Column(UUID(as_uuid=True))`。
- **建议**：统一为 `UUID(as_uuid=True)` 或显式在 ORM 关系中使用 `ForeignKey`。

### 13. 单元测试覆盖不足
- **问题**：新增功能（Skill 解锁/分成、ima 搜索、资产上传限额、审计日志清理、模型白名单等）缺少自动化测试。
- **建议**：补充 pytest 覆盖核心路径。
