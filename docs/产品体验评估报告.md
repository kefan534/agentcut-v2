# AgentCut 产品体验评估报告

**评估时间：** 2026-07-26  
**评估角色：** 产品经理（端到端体验 + 技术可行性视角）  
**评估范围：** 首页、登录/注册、创作工作区（文/图/视频）、Agent 控制台、无限画布、历史记录、设置、管理后台  
**结论前置：** 目前网站属于"功能可用、但距离可上线还有明显 gap"的阶段。Agent 与画布完成了从 0 到 1 的框架，但核心链路存在多个可能直接导致用户流失或资损的重大问题。

---

## 一、严重问题（P0 / 必须阻塞上线）

### 1. 历史记录接口无分页，存在性能与崩溃风险
- **现象：** `/api/history` 返回当前账号全部生成记录。测试账号一次性返回 **221 KB** JSON。
- **影响：**
  - 用户使用一段时间后，打开历史记录页面会越来越慢；
  - 大用户量或长历史时，浏览器可能出现长列表渲染卡顿甚至白屏；
  - 服务端每次全表查询，数据库压力线性增长。
- **建议：** 必须加分页（`page/limit` 或游标）、前端虚拟滚动、以及后端默认时间倒序 + 索引。

### 2. 创作入口重复，导航逻辑混乱
- **现象：** 系统同时存在两套创作页面：
  - `/create/image`、`/create/video`（早期页面，左侧参数面板 + 右侧结果面板）
  - `/workspace/image`、`/workspace/video`、`/workspace/text`（新工作区，聊天式/底部输入式）
- **影响：**
  - 顶部导航"创作"指向 `/workspace/image`，但 `/create/*` 仍可访问，造成用户路径分叉；
  - 两套页面功能重叠、UI 风格不同，维护成本高；
  - 用户在不同页面生成内容，历史记录里无法区分来源，体验割裂。
- **建议：** 保留一套创作入口，将 `/create/*` 重定向或下线，统一走 `/workspace/*`。

### 3. 文本生成与图/视频生成的交互模式不一致
- **现象：**
  - 文本对话：前端同步等待 `/api/generate/text` 返回，超时 60 秒，期间按钮 loading，用户只能干等；
  - 图像/视频：创建任务后异步轮询 `/api/task/:id`。
- **影响：**
  - 文本模型一旦响应慢或失败，整个请求挂死，用户无法取消；
  - 长文本/复杂推理场景下极易超时，前端报错"Generation failed"；
  - 三种创作形态的进度感知、失败重试、取消机制都不统一。
- **建议：** 文本生成也应走"创建任务 → 轮询/流式输出"模式，或至少支持 SSE 流式返回，与图像/视频统一任务中心。

### 4. Canvas 画布存在React Flow API兼容性与状态同步bug
- **现象1：** `canvas/page.tsx` 中使用了自定义 shim（`applyNodeChanges`/`applyEdgeChanges`/`addEdge`）而非 `@xyflow/react` 官方导出函数，与 v12 API 不完全对齐。
- **现象2：** `onNodeDragStop={() => commit(nodes, edges)}` 与 `onMoveEnd` 捕获的是闭包中的旧 `nodes/edges`，拖拽后保存的位置可能是上一帧状态。
- **影响：**
  - 节点拖拽、连线、删除等操作在复杂场景下可能出现位置回跳、连线丢失、撤销重做异常；
  - 复制粘贴逻辑中只复制了节点，没有正确复制边（`rawEdges` 读取的 key 与写入的 key 不一致）。
- **建议：** 升级到 `@xyflow/react` 官方推荐写法，使用 `useNodesState`/`useEdgesState` 或从包中导入工具函数；修复 `onNodeDragStop` 闭包问题。

### 5. Token 过期/失效无前端感知，导致"假登录"
- **现象：** `AuthContext` 只在 mount 时读取 localStorage，后续 API 返回 401 时没有任何统一处理。
- **影响：**
  - token 过期后，页面仍显示已登录状态，用户点击生成时才会报"Unauthorized"或"登录态失效"；
  - 管理后台、工作区、Agent 各自报错，体验不统一；
  - 登录态异常时没有自动跳转登录页。
- **建议：** 封装全局 fetch 拦截器，遇到 401 统一清除登录态并跳转 `/login`；`refreshUser` 增加 token 过期检测。

### 6. Agent 控制台状态存在内存中，生产不可用
- **现象：** Agent thread 状态保存在 Node 进程内存（`thread-store.ts` 的 Map），`MemorySaver` 也无法解决多实例问题。
- **影响：**
  - 服务重启后所有对话和分镜方案丢失；
  - 多实例部署时，SSE 可能连到不同实例，导致状态不一致或事件丢失；
  - 无法做水平扩展。
- **建议：** 用 Redis / PostgreSQL / SQLite 持久化 checkpointer；SSE 与任务执行需要集中式事件总线。

### 7. 积分扣减与退款逻辑不一致，存在资损风险
- **现象：**
  - 图像/视频：扣积分 → 异步任务 → 失败时退款；
  - 文本：扣积分 → 同步等待 → 失败时退款；
  - 但图像/视频的"退款"是在异步回调里执行，如果回调本身抛异常或进程重启，用户积分不会退回。
- **影响：** 用户扣了积分但没有拿到结果，客诉与资损风险高。
- **建议：** 引入统一任务表 + 幂等退款机制；关键资金操作写 `Order` 流水，并做定时对账兜底。

## 二、中等问题（P1 / 显著影响体验，建议近期修复）

### 8. 注册/登录缺少基本校验与安全措施
- 手机号没有正则校验，可输入任意字符；
- 密码只有 `minLength=6`，无强度提示；
- 没有验证码/防暴力破解机制；
- 注册后只送 10 积分，做一条视频（30 秒 = 900 积分）完全不够，新用户首次体验门槛高。

### 9. 缺少全局错误边界（Error Boundary）
- 当前没有 `error.tsx` 或 `ErrorBoundary`；
- 任一组件 render 异常都会导致整页白屏，尤其对复杂 Canvas / Agent 页面风险大。

### 10. 移动端/响应式体验差
- 所有页面都是桌面端固定布局，小屏下左侧边栏、Agent 三栏、Canvas 工具栏都会重叠或无法操作；
- 在当前用户以移动端为主的环境下，这直接限制了可用人群。

### 11. Agent 新建对话的 ID 处理有问题
- `useAgent.newThread()` 直接在前端生成 `crypto.randomUUID()` 并写入 localStorage；
- 此时该 ID 并不存在于后端，页面显示空状态；用户发送第一条消息后才会真正创建 thread；
- 如果用户刷新页面，会看到一个"不存在"的 thread ID，可能报查询失败。

### 12. 视频生成参考素材支持不完整
- `/api/generate/video` 支持 `videos`/`audios` 字段，但前端 `/workspace/video` 只上传 `images`；
- "参考生视频"模式（r2v）实际上没有把视频文件传上去，功能名不副实。

### 13. 历史记录中文本结果展示方式不自然
- 文本对话结果存储在 `resultUrls` 字段（JSON 数组的第一个元素），语义上是 URL 字段被当作文本用；
- 历史卡片里把长文本直接塞进一个 `overflow: auto` 的 div，阅读体验差。

### 14. 管理后台权限校验在客户端完成
- `/admin/layout.tsx` 通过 `useAuth` 判断 role 后跳转，理论上服务端 API 也会校验，但页面渲染层存在短暂显示或闪烁风险；
- 建议在服务端 `requireAdmin` 统一拦截，并增加服务端渲染/loading 状态。

## 三、体验与细节问题（P2 / 打磨项）

### 15. 页面主题风格不统一
- 首页、登录、注册、管理后台是浅色主题；
- 工作区、Agent、Canvas、历史记录是深色主题；
- 两套主题切换没有过渡，用户从注册进入工作台会有明显"换了一个产品"的感觉。

### 16. 部分交互元素使用 emoji 代替图标
- 导航、工具栏、节点类型大量依赖 emoji（🖼️、🎬、🤖、📎 等）；
- 在不同操作系统/浏览器下渲染不一致，且显得不够专业；建议统一使用 SVG 图标库。

### 17. Agent 底部输入栏的"附件"按钮无功能
- `BottomInput` 中有 📎 上传按钮，但点击没有任何响应，没有 `onUpload` 或文件选择逻辑。

### 18. 输入框缺少字数/ token 提示
- 图像、视频、Agent 的提示词输入框都没有字数统计；
- 对于长 prompt 或模型限制，用户容易超字数导致失败。

### 19. 构建阶段存在 Dynamic Server Usage 警告
- `npm run build` 时出现 `Route /api/agent/threads couldn't be rendered statically because it used request.headers`；
- 虽然构建最终成功，但说明路由静态生成策略需要显式标记 `export const dynamic = 'force-dynamic'`。

### 20. API 错误提示不够友好
- 多处直接返回 `apiError(err.message, 500)`，例如模型渠道不可用时用户看到"No available image generation channel"；
- 建议根据错误类型映射为中文用户友好提示，并给出可操作建议（如"当前生图渠道繁忙，请稍后重试"）。

## 五、当前做得还可以的地方

1. **Agent 流程框架已跑通**：从意图分析 → 澄清反问 → 分镜方案 → 确认 → 逐帧渲染 → 合成的完整链路在 Demo 模式下可复现，产品方向正确。
2. **SSE 实时推送已接入**：Agent 状态变化能通过 EventSource 同步到前端，进度感知体验在线。
3. **网关抽象清晰**：`GATEWAY_BASE_URL` + `AGENT_DEMO_MODE` 的配置方式便于本地调试与线上切换。
4. **积分体系有基础**：扣费、退款、余额展示都有实现，虽然不够健壮，但骨架已具备。
5. **历史记录 Lightbox 体验**：图片/视频点击放大、下载、复制链接等功能已具备。

---

## 六、综合建议：下一步应该做什么

### 第一阶段（1-2 周，修 bug 保可用）
1. 历史记录分页 + 任务中心统一；
2. 修复 Agent 内存状态持久化（Redis/SQLite）；
3. 统一登录态 401 处理；
4. 修复 Canvas React Flow 状态同步 bug；
5. 下线 `/create/*` 或统一重定向。

### 第二阶段（2-3 周，体验打磨）
1. 文本生成异步化或 SSE 流式；
2. 积分退款幂等 + Order 对账；
3. 全局 Error Boundary + 友好错误提示；
4. 注册校验、新用户额度、密码强度；
5. 移动端响应式适配。

### 第三阶段（1 个月+，产品化）
1. 任务队列与失败重试机制；
2. 用户引导/空状态/新手教程；
3. 埋点与数据看板；
4. 多渠道 AB 与模型路由策略优化；
5. 性能优化（图片懒加载、大列表虚拟化、Bundle 拆分）。

---

**总结一句话：** 功能骨架已经搭起来，但 P0 级别的稳定性、一致性和资损问题必须先修，否则不建议对外放量。
